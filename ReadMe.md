# BrowserStack Mobile Automation

## Summary

This project contains mobile UI automation tests for the Android Native Demo App.

The project uses:

- WebdriverIO
- Appium
- UiAutomator2
- BrowserStack
- Mocha
- Appium Inspector

The tests are executed on Android devices hosted by BrowserStack.

The project contains 5 automated test cases covering different parts of the application and different mobile interactions such as click, tap, and swipe.

Two WebdriverIO configuration files are provided for testing on different Android devices.

## Requirements

Before running the project, install:

- Node.js
- npm
- Git

You also need:

- A BrowserStack account
- BrowserStack Username
- BrowserStack Access Key
- Android Native Demo App uploaded to BrowserStack

The project uses the following environment variables:

- BROWSERSTACK_USERNAME
- BROWSERSTACK_ACCESS_KEY

The BrowserStack application is identified by the following custom ID:

TimofiiNativeDemoApp

## Installation

Clone the repository:

    git clone <YOUR_REPOSITORY_URL>

Open the project directory:

    cd browserstack_test

Install dependencies:

    npm install

For a clean CI installation, use:

    npm ci

## Launch Tests

### Run tests on Google Pixel 6

    npx wdio run wdio.conf.js

The default configuration uses:

- Device: Google Pixel 6
- Android version: 12.0

### Run tests on Google Pixel 7

    npx wdio run wdio.android.pixel7.conf.js

The second configuration uses:

- Device: Google Pixel 7
- Android version: 13.0

Both configurations execute the same five test cases.

## Test Cases

The project contains five automated test cases:

1. Login form validation
2. WebView navigation
3. Forms page verification
4. Drag and drop interaction
5. Swipe carousel interaction

The tests use locators identified with Appium Inspector.

The Page Object Model is used to separate page locators and interaction methods from test scenarios.

The test data for input fields is generated dynamically where required.

## Test Report

Test results are generated by WebdriverIO and Mocha.

If Allure results are generated, they are stored in:

    allure-results/

To generate an Allure report, run:

    npx allure generate allure-results --clean -o allure-report

To open the generated report, run:

    npx allure open allure-report

The generated Allure result and report directories are excluded from Git using .gitignore.

## GitHub Actions

The project contains a GitHub Actions workflow:

    .github/workflows/mobile-tests.yml

The workflow runs the automated mobile tests on BrowserStack.

BrowserStack credentials are stored as GitHub repository secrets.

The required secrets are:

- BROWSERSTACK_USERNAME
- BROWSERSTACK_ACCESS_KEY

The workflow passes these secrets to WebdriverIO through environment variables.

The workflow can be triggered by pushing changes to the main branch or manually from the GitHub Actions interface.

## BrowserStack Configuration

The default configuration uses:

- Device: Google Pixel 6
- Android version: 12.0
- Automation: UiAutomator2

The second configuration uses:

- Device: Google Pixel 7
- Android version: 13.0
- Automation: UiAutomator2

Both configurations use the same BrowserStack application custom ID:

    TimofiiNativeDemoApp

## GitHub Secrets

The following repository secrets must be configured in GitHub:

- BROWSERSTACK_USERNAME
- BROWSERSTACK_ACCESS_KEY

These values must not be stored directly in the source code.

The WebdriverIO configuration reads them from environment variables:

- BROWSERSTACK_USERNAME
- BROWSERSTACK_ACCESS_KEY

## Running the Project Locally

To run the default configuration:

    npx wdio run wdio.conf.js

To run the second device configuration:

    npx wdio run wdio.android.pixel7.conf.js

Both configurations should complete successfully before pushing the project to GitHub.
